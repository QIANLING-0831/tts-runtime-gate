# TTS 竞品实测与迁移评估

## 目标

本轮测试不比较谁的指标更多，而是回答三个问题：

1. `open-tts-eval` 与 `TTSProof` 中哪些能力可直接复用；
2. 当前 `narration` 中哪些代码应删除、保留或改造成适配层；
3. 中文本地 TTS 的生成、候选择优、失败恢复和后处理复检是否仍有独立价值。

任何工具只有在相同音频、相同期望文本和相同失败定义下才允许横向比较。

## 固定基线

- 黄金听感样本：`narration/runs/smoke/narration-gentle.wav`
- 对应文本：`人工智能正在改变我们的学习方式。`
- 当前声音配置：Furina GPT `e15` + SoVITS `e8`
- 当前自动审核：本地 Whisper、静音、削波、边缘静音、局部音高警告
- 当前已知限制：固定 seed 在模型重载后不保证波形级复现；简单频谱代理不能可靠判断电音感。

## 测试语料

至少准备以下六类，每类不少于 5 句；最终建议 40–60 句。

1. 普通陈述句：用于测基本自然度和稳定性。
2. 数字与单位：年份、百分比、金额、小数、日期和区间。
3. 中英混读：AI、AIGC、GDP、API、英文人名和产品名。
4. 多音字及专有名词：银行、重庆、经贸合作等上下文相关读法。
5. 长句与标点：逗号、分号、括号、引号和连续从句。
6. 易失败样本：短句、问句、重复词、高情绪句和过去出现电音/拖音的位置。

每条语料保留 `display_text` 与 `provider_text`，禁止为了提高 ASR 分数悄悄改变原意。

## 第一层：确定性技术测试

所有系统检查同一批 WAV：

- 音频可解码、采样率和声道合法；
- 空文件、过短音频、削波、首尾超长静音；
- 句中异常静音、重复片段、拖长音、尾部 click；
- ASR 漏字、错字、重复字；
- 指标异常、NaN 或模型加载失败时必须 fail closed，不能默认为通过。

预期产物是逐句结果，而不是只有总体平均分。

## 第二层：故障注入

从正常样本复制并人工制造以下缺陷，用来确认审核器真的能抓住错误：

- 删除一个词；
- 重复一个音节或一小段；
- 中间插入 0.5 秒静音；
- 开头或结尾插入 1 秒静音；
- 放大到明显削波；
- 截断尾字；
- 加入尾部 click；
- 对局部做明显金属化处理。

每个审核器记录真阳性、漏检和误报。没有故障注入的数据不能证明质量门有效。

## 第三层：盲听真人感

自动指标不得决定“真人感”是否通过。试听文件匿名随机编号，至少比较：

- 原始生成；
- 当前轻处理版本；
- 不同 seed 候选；
- 后续接入的第二种本地 TTS；
- 如条件允许，加入一条真人录音作为锚点。

每条按 1–5 分记录：

- 电音/金属感：1 严重，5 不明显；
- 发音正确性；
- 停顿自然度；
- 韵律和句尾；
- 整体可用性。

另外记录强制选择：`可直接用 / 可轻修 / 必须重生成`。先听后查看模型、seed 和自动分数。

## 第四层：生产闭环测试

对每种失败验证系统动作，而不只验证报表：

- 候选失败后自动换 seed；
- 所有候选失败后进入 `REVIEW_REQUIRED`；
- 后处理前通过、后处理后失败时禁止放行；
- ASR 或指标模型不可用时禁止伪造通过；
- 最终 manifest 能追溯文本、模型、权重、seed、原始候选、后处理和选择理由。

这部分是本项目与通用 evaluator 最重要的差异。

## 竞品执行顺序

1. 在隔离临时目录安装并运行 `open-tts-eval`；
2. 用同一批 WAV 和文本运行 `TTSProof`；
3. 将两者输出映射到统一的 `PASS / REVIEW_REQUIRED / REJECT`；
4. 对照当前流水线的漏检、误报、运行时间和依赖成本；
5. 形成迁移表：`直接复用 / 包装调用 / 保留自研 / 删除`。

## 已完成的竞品基线（2026-09-29）

- `TTSProof 0.4.0`：隔离环境中 59 项测试通过、1 项跳过；黄金样本结构检查为 `pass`。
- `open-tts-eval 0.1.0`：136 项测试通过、1 项在中文 Windows 的 GBK 默认编码下失败；失败发生在测试代码读取 UTF-8 HTML 时未指定编码，并非评测算法失败。
- `open-tts-eval` 在未安装 ASR 后端时将黄金样本判为 `fail:asr`，符合 fail-closed 预期。
- 安装 ASR 并强制 CPU 后，`open-tts-eval` 将中文音频转写为英文，随后用 `english-basic` 归一化器得到空的中文期望文本并判定失败。这证明其当前默认链路不能直接承担中文审核，必须增加中文 ASR/normalizer 配置或适配。

迁移判断：不复制两者代码。通用结构检测与报表以它们为参照；本项目只维护 GPT-SoVITS 生成编排、中文文本处理、多候选恢复和后处理复检。

## 发布门槛

满足以下条件后再作为独立仓库发布：

- 竞品在同一数据集上的实测完成；
- 至少 40 条中文测试语料和一组故障注入样本；
- 至少一轮匿名盲听标签；
- 接入一个非 GPT-SoVITS 本地模型；
- 重复能力已有明确复用或保留理由；
- README 明确区分技术通过与人工表演/真人感批准。

匿名盲听工具已生成三份随机样本：GPT-SoVITS 原始版、GPT-SoVITS 轻处理版

## 当前人工结论

首次匿名排序为 `C > A > B`。揭盲后：C 是 GPT-SoVITS 轻处理版，A 是普通
母带版，B 是 Windows SAPI。B 被听者明确判定为纯电音，因此只保留为第二
提供者的接口与技术审核验证，不作为可用声音。C 被选为当前 Furina 声音唯一
的黄金听感参考；A、B 不进入参考集合。

对 C 追加两档极轻的高频收敛处理后，听者认为三者区别不大。因此不继续堆叠
EQ、降噪或压缩：当前残留的空灵感更可能来自参考音频或模型生成本身，继续
后处理的收益很低，并可能让声音发闷或重新产生电音。
